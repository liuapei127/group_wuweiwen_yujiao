# 学生助手独立更新：代码与 Dify 画布

分支：`codex/student-assistant-update-20261118`。本次独立提交包含从上次拉取的 `1400755` 基线之后的学生模块改动，供组长审阅和合并；没有合入 main 或原整合分支。

## 修改内容

- 姓名、班主任、班级、专业等本人问题按登录账号取正式资料，直接自然回答；完整学籍请求仍显示资料卡。称呼记忆与正式姓名分开。
- 混合问题可以同时使用所问的正式字段和本账号明确自述，例如“我喜欢吃什么，我是谁”。模型和检查器接收同一份本轮证据，避免生成时能看见资料、检查时却不认识资料。
- 知识详情保留学生原问题和国家，兼容没有 short_answer 的原展示记录，展开相关指南已有步骤；无新增内容时不显示无意义的详情入口。德国和新加坡共用同一套处理。
- 增加具体个人字段、数字、卡种、机构、渠道、操作承诺等检查；实体别称须以知识正文中已有实体为依据，不能由别称推导新的产品、渠道或费用。
- 资料检查拦截后，保留已展示的检查通过内容，补齐缺少的后端可靠回答，减少半句回答、重复姓名及步骤换行丢失。真实超时或连接异常仍会提示。
- 保留原来的账号隔离、草稿确认、请假和反馈联动。独立关怀业务与真实 Mem0 接入不在本次修改范围。

## 画布导入

本目录 `dify/stu-workspace.yml` 是本机当前**已发布版本**的原生 YAML 导出，22 节点；发布编号、SHA256 和验证记录见 `manifest.json`。`docs/dify/local-integration/stu-workspace.yml` 同时保留可审阅的开发定义；组员导入优先使用本目录的原生导出。

1. 在自己的 Dify 导入 `dify/stu-workspace.yml`，配置可用的模型供应商及插件（导出包含通义插件依赖，当前模型 qwen-plus）。
2. 重新绑定德国、新加坡两份外部知识库；对应 knowledge_id 为 Germany、Singapore。将外部知识接口配置为目标 Dify 容器可访问的后端 `/api/v1/student/knowledge`，填写该环境自己的 STU_KNOWLEDGE_TOKEN。
3. 发布后，在后端本机环境配置 STU_ASSISTANT_MODE=workspace、STU_DIFY_API_KEY 和 DIFY_API_URL。工作流必须配合本分支代码使用。不要把原开发电脑的应用 Key、数据库连接或私钥复制到仓库。
4. 重启后端，刷新学生页面，重新发送问题查看新回复。旧消息保留原样，不会自动重写。

本次不需要迁移数据库或重导知识。知识正文继续读取原展示库的海外生活知识表；新增的检查与详情整理兼容原快照。完整环境和原展示库准备见 [原展示交付说明](../2026-11-18/README.md)，其中学生画布应使用本目录的新版本。

## 实际回答路径

后端确认学生与会话归属，读取本会话最近20条消息（约10轮）、最多5条相关个人记忆、本人资料和草稿。普通个人问题/生活知识由后端选择事实或正文，再交给 Dify visible_reply 节点组织回答；复杂办理文本可先让理解节点提取信息，业务仍在后端核对和确认后执行。画布的22个节点不会每次都全部运行。

本机长期记忆存储在 stu_mem0_memory，短期历史存储在 stu_assistant_message。当前未配置真实 Mem0 服务。新对话切换短期历史，同账号的有效长期记忆仍可召回；聊天自述不能修改正式学籍或授权提交。
