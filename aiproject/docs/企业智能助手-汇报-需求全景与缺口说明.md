## 一、我到底要交付什么（范围说明）

ENT 在「教育服务 AI」里负责 **企业侧智能助手**：顾问/员工通过 **Dify 对话** 完成录入、查询、改状态、日报、审批、口语查库等；底层由 **FastAPI** 写库、读库，表结构以团队 `db_init.sql`（31 表）为准。

**你负责的边界**：

- `aiproject` 内 ENT 相关模块与文档、本地/评审级测试。  
- **不负责**：擅自改腾讯云、执行生产库 DROP、代替集成负责人做公共登录、代替 STU 负责人做学生端请假/投诉全链路。

**云端现状（已确认）**：仅 `GET /health`、`GET /health/db`；Dify 调库健康 OK；**ENT 业务 API 未上云**。

## 三、工程与质量需求（评审/GPT 强加于客户管理阶段的）

这些不是 Excel 里的业务行，但**不完成就不能宣称可发布**：

| # | 需求 | 含义 |

## 五、未实现或未验收项 — 原因说明（汇报重点）

### 1. 可信员工身份与全模块可发布（E1/E2）

**未做到什么**：JWT、网关注入员工 ID、`sys_user` 有效性、经理数据范围。  
**已做到什么**：默认 `EMPLOYEE_IDENTITY_MODE=blocked`，consultant **503**；隔离脚本证明旧模式可 **KNOWN_DEFECT** 冒用。  
**原因**：公共 `modules/auth` **不在 ENT 仓库、无集成负责人书面契约**；评审禁止自行造登录或生产放行开关。  
**需要组里做什么**：指定集成负责人，敲定 issuer/audience、网关头、Dify 服务账号与员工代理规则（见 `回复Cursor/04` 三栏表）。

### 2. Dify 企业 Chatflow 闭环（场景 1–3 的产品形态）

**未做到什么**：意图、追问、调 API、失败话术、云端 `education-api` 联调。  
**原因**：业务 API **未上云**；身份未定时不宜配置生产 Chatflow；客户管理阶段优先 **API + 评审补测**。  
**需要组里做什么**：合并 `aiproject` 并 build `api`；提供 Bearer/未来 JWT 约定；ENT 再配 HTTP 节点。

### 3. 腾讯云部署（E8）

**未做到什么**：除 health 外 ENT 路由在云上可访问。  
**原因**：任务边界 **「未授权不改云」**；需团队 merge + compose 合并文件后由负责人执行 build。  
**需要组里做什么**：集成合并、`docker compose -f compose.yaml -f aiproject/compose.*.yaml up -d --build --no-deps api`。

### 4. Python 3.13 干净安装 / Docker（E6）

**未做到什么**：双 venv `pip install` exit 0、Docker 镜像构建记录。  
**原因**：本机 Windows **仍为 Python 3.10**；PyPI **SSL** 曾阻塞；**Docker 3.13.18** 下 build + import 已有证据（`34-Python313安装与构建证据.json`）。
**需要组里做什么**：腾讯云 API 容器按 `33` 重建；可选本机安装 3.13 与 Docker 对齐；Windows 本机开发可暂用 3.10 跑脚本，交付以 3.13 镜像为准。

### 5. GPT 第五轮仍缺的 HTTP（P2）

**未做到什么**：每次 403 前后库快照全集、A/B 客户列表隔离、PATCH 档案、`PATCH /leads/{id}`、非法员工头 0/负数、DB 故障注入等。  
**原因**：人力与轮次优先 **P1 默认拒绝 + 双套件**；部分用例需两员工测试数据与更长脚本。  
**需要组里做什么**：排期补 `06` 清单 §4；不阻塞「阶段材料」但阻塞「客户管理可发布签收」。

### 6. ENT-06/07/08/10/13（组织、新人、成绩、投诉、主动待办）

**未做到什么**：对应 API 与 Dify 能力。  
**原因**：项目与 GPT 修订顺序 **「客户管理 + 认证 + 上云」优先**；成绩/投诉等明确 **分期**；表在 31 库中已有但 **无业务代码**。  
**需要组里做什么**：产品确认二期排期；投诉/请假依赖 **木合塔尔** STU 契约。

### 7. ENT-04/05 口述日报「端到端」

**未做到什么**：语音→结构化→入库的 Dify 全链验收。  
**原因**：分工上 **Dify 负责 NLP**；API 仅占位收 JSON；夏登东汇总 RPT-02 **未联调**。  
**需要组里做什么**：Dify 语音/抽取节点 + 字段格式与 `employee_daily_report` 对齐。

### 8. ENT-05 部门维度与经理权限

**未做到什么**：按部门查日报、经理看下属。  
**原因**：表/接口 **无 department 字段与 RBAC**；依赖组织与 auth 契约。  
**需要组里做什么**：数据模型扩展 + 身份角色定义。

### 9. NL2SQL 数据范围（C1）

**未做到什么**：员工只能查权限范围内数据。  
**原因**：与 **E1 身份** 同源阻塞；当前白名单 intent 无员工绑定测试。  
**需要组里做什么**：身份落地后补 intent 与 `operator_id` 绑定策略。

### 10. 本地库 DROP 与「31 表一致」表述

**未做到什么**：不能向领导宣称「已证明未破坏团队共享库」「31 表逐表完全一致」。  
**原因**：曾在 **本机可丢弃** `education_service` 上跑过含 DROP 的 `db_init`；CRM 仅 **列名级 diff_count=0**，非 29 表全量 diff。  
**需要组里做什么**：测试/预发用 **无 DROP 迁移**；共享库由 DBA 管。

## 六、建议对领导说的三句话

1. **客户管理后端 API 在本地已实现，并经过多轮 HTTP 补测**；但 **默认配置下员工业务已按安全要求关闭（503）**，要等公共认证契约后才能对外开放和接 Dify。  
2. **云端、Dify、可信登录、安装打包、请假/投诉/成绩等扩展场景均未验收**，多数原因是 **跨负责人阻塞** 或 **明确分期未开工**，不是单项偷懒。  
3. **下一步关键路径**：(①) 集成负责人定 auth → ENT 实现 trusted 模式并重跑 spoof；(②) 合并上云 build；(③) 客户 Dify 闭环；(④) 与 STU/夏登东契约后做请假与日报。
