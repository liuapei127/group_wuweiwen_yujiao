## 三、四句话开场（建议直接念）

1. **客户/日报/请假/指令/查库等接口代码都在本地有了**；客户权限在 **演习场（repro）** 测过并有限签收，**不等于** 真实 JWT 已验收。

3. **云上仍以 health 为主**，业务 API 要合并代码后 **Docker 3.13 重建**；Dify 企业流 **还没端到端验收**。  
4. **当前瓶颈**：① 公共 auth 负责人定 JWT；② 上云 build；③ Dify+STU 联调请假/日报。

## 五、和别的模块要什么（会上分锅用）

**必须有人拍板的一条**：**公共 auth** — JWT 字段、Dify 服务账号、停用员工怎么办（填 `回复Cursor/04` 表）。

| 找谁 | ENT 需要什么 |
| --- | --- |
| **集成 / auth** | 书面契约 → ENT 做 `trusted_jwt`，再开放 503 以外的业务 |
| **Dify 同学** | 企业 Chatflow；内网 `http://education-api:8000`；NL2SQL **不准传 SQL**；auth 后带 Authorization |
| **STU（学生助手）** | 请假进库字段样例；pending→approved **一条链路联调** |
| **RPT（日报汇总）** | 与 `employee_daily_report` 字段对齐 |
| **files（附件）** | 上传 URL 规范后 ENT 接客户附件字段 |
| **组长 / 运维** | 云路径合并、`compose --build` API 3.13；约定传代码方式（Git/SCP） |

**ENT 承诺**：不私自造登录、不恢复客户端 `X-Employee-Id` 当生产身份；`tests.repro` 演习场 **不删**（以后测业务规则用）。
