# 客户研判改动说明

分支 `codex/v11-integration`。只动客户研判这一条：工作流按已入库的客户记录写顾问建议，知识库补齐项目条款，页面从游客跟进里拆出来。游客录入、CRM、规则初筛的状态判定、其他 Dify 应用都没有改。

工作流 DSL 在 `pf.yml`，四份知识库正文在 `pf-knowledge/`。25 次对照结果在 `pf-测试报告-2026-11-15.md`。

## 数据从哪来

研判读的是 `customer_source.raw_content`，也就是已经入库的这一位客户记录。工作流输入变量仍叫 `raw_content`，值由后端预览接口从这张表取出。一位客户一份记录。记录可以是一个 JSON 对象，也可以是只含这一位的数组。`id` 不参与判断。一份里放进多位客户时，结论是暂不推进。

`crm_lead` 不是研判来源。规则初筛仍走原来的代码，不读知识库。

## 工作流

应用是「客户研判」。节点顺序：

1. 用户输入。没有附件时走粘贴正文，有附件时先提取文件正文。
2. 合并正文。
3. 画像研判。代码节点做硬性核对，结论只取四个：可以推进、需要补充信息、建议调整方向、暂不推进。同时给出产品、方向、评分，以及给检索用的查询词。
4. 检索研判规则。知识库「客户研判规则」，按这位客户的查询词取 4 条，不做重排。
5. 顾问建议。通义 qwen-plus，温度 0.3。结论必须沿用代码节点的结论。话按这一位客户的记录、核对结果和检索到的条款来写，按四句输出：结论、沟通时可以这样说、还缺这些资料、下一步先问。条款里没有的费用、录取和承诺不写。
6. 输出。`match_result`、客户姓名、产品、评分、推荐方向仍来自代码节点。`match_reason` 是顾问建议的正文，页面上原来展示这段话的位置不用改。

本机知识库编号 `8daaee59-1cdf-4377-830d-eed3b0f7ff8f` 写在 `pf.yml` 里。换工作区时要重建知识库并改这个编号。

## 知识库

知识库名称是「客户研判规则」。仓库里的四份正文和线上文档一致：

| 文件 | 给检索用的内容 |
| --- | --- |
| 用户画像研判规则.txt | 新加坡、德国的年龄、学历、语言、诉求和材料要求。新加坡入学含英语笔试、心理测评和口试。德国匹配企业前需要德语 B1。 |
| 中德专业方向名录.txt | 16 个德国专业的中文名、德文名、训练内容和对应企业。线上按六个方向各成一段，避免一张表被切散。 |
| 新加坡国际本硕升学计划.txt | 2+2、2+2+1、0.5/1+2、0.5/1+2+1、一年制专升本和本升硕、6+6 酒店、9+6 航空，以及学费和入学测试。 |
| 中德精英人才共建计划.txt | 年龄 18–35、高中及以上、办理流程、德语 B1 后再匹配企业、机电补贴示例和就业薪资。 |

两份项目说明按空行分段，每段最多 800 token，避免学费表和流程被从中间切开。《用户画像研判规则》仍按自动分段。原文在「如项目与一带一路、乡村振兴相关联」处结束，说明里没有补写结尾。

德国项目原文有两处永居说法：办理流程写工作两年后可申请，项目特色写连续工作五年。两处都保留，说明里不改其中一处。

不放进这个知识库的文件：用户信息数据示例（那是输入，不是规则）、新加坡和德国的通用留学政策指南、客服用的公司简介和常见问题。

## 页面

员工工作台侧栏有「客户研判」，路径 `/profile-screening`，权限沿用 `crm:read`，提交资料沿用 `crm:write`。游客跟进里不再放客户资料录入。

页面仍是：提交或查看 `customer_source`，运行 Dify 研判，下面保留原来的规则初筛表单。

## 结果落在哪里

| 动作 | 写入 |
| --- | --- |
| 上传资料 | `customer_source` |
| 规则初筛 | `customer_profile`，只保存规则核对，操作者取当前登录员工 |
| 运行 Dify 研判 | 不落库。预览读出正文后回滚，建议只返回页面 |

门户按钮要能调到已发布工作流，服务端需要配置 `PF_DIFY_API_KEY`。未配置时按钮返回 503，Dify 工作室里仍可直接看运行记录。

## 已核对的运行

2026-11-15 用《用户信息数据示例》U_001 到 U_020，加上空正文、一份里两位客户、自由文本、只有姓名、初中却报德国，共 25 次跑当前工作流。八个节点都成功。结论、产品、分数、方向和缺资料与代码节点一致，顾问建议的第一句结论没有改掉代码结论。

话术后半段仍会超出规则核对：代码写没有缺关键资料时，模型有时继续追问成绩单、护照或银行流水。自由文本的德国案例还写出了条款里没有的补贴区间。明细见测试报告。

顾问建议没有写回 `customer_profile`。
