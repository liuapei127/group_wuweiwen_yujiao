# 学生服务：自然交流、知识与分步办理

本轮在现有项目分支 codex/student-module-integration 整合学生模块；本机沿用原学生助手应用 e0665430-6cd8-4c88-b4e4-ce2f74e19cbc。旧工作流版本保留，升级前的画布和运行配置另存于忽略跟踪的 logs/student-dify-before-integration.json、logs/student-runtime-before-integration.json。其他 Dify 应用继续使用原配置。

## 学生体验

默认欢迎首页显示本人已登记的申请/考务/通知。助手支持普通聊天与适度建议，先澄清抱怨和诉求；请假与反馈按类别、时间或业务范围、具体情况逐步引导。学生核对后确认，才产生业务记录和员工待办；反悔可取消。查看资料或聊天可以暂停办理，再继续。独立自评与关怀模块保持原样。

## 画布

输入本人上下文 -> 语义分流与格式校验 -> 三路：

1. 自然交流：结合近期对话与自述记忆组织温和、具体、不过度承诺的回复。
2. 公开知识：按国家选择德国或新加坡外部知识库，检索核对内容，回传采用的知识编号与建议回答。后端再核对本国候选FAQ，关键事实直接取自核对记录，附出处。
3. 办理或本人查询：交回后端；本人事实由授权学生编号读取，办理状态由持久草稿控制，模型不执行业务。

当前共18节点，导入文件 docs/dify/local-integration/stu-workspace.yml 中的知识库ID为本机绑定；迁到其他工作区时替换为该环境的两个知识库ID。知识库在Dify可查看为“学生生活指南 · 德国”和“学生生活指南 · 新加坡”。不得在 workspace 模式下使用旧 stu.yml 自动办理回调；后端会拒绝该回调，避免绕过草稿确认。

## 与当前业务的衔接

- 项目、班级与学籍继续使用现有班级管理数据。学籍页只读显示所属项目、当前班级、班主任和院校专业；转班后按现有入班记录显示，不另建学生档案。
- 请假确认复用现有请假及待办服务；原表单仍支持可选证明附件，老师审批和结果通知继续沿用。学习反馈交班主任，公司反馈按既有主管配置分派；管理员、主管的纠错和重新分派入口保留。
- 预科、语言培训、海外院校三个教学阶段、整班考务、课程与成绩、更换班主任时的未完成事项交接继续使用当前实现。
- 游客预约补姓名、登录联系方式默认值、游客昵称、上传材料查看与识别导入、客户研判、员工日报、企业助手等沿用当前代码。
- 助手生成草稿时不写请假或反馈单；确认请求按学生归属、草稿版本和状态验证。业务单、员工待办和办理回执同事务保存；重复确认返回原回执。会话可暂停、恢复，草稿24小时过期。

## 知识与维护

目录overseas-life-catalog.json，12篇图文指南，德国/新加坡各6类、各18个FAQ。每篇含步骤、适用范围、来源及核对日期，联系方式均来自官方来源。页面与助手读取同一份数据库记录。图片仅为场景示意。

当前采用关键词和问题片段排序；没有声称已使用向量检索，也没有实时地图、天气、预约或自动拨号能力。学校资料不足时不编造。

先应用pending/028迁移（依赖027），再执行python scripts/import_student_life_catalog.py --database 明确目标库名。导入具备同源和目标库校验，不擅自覆盖其他来源同名记录。

Dify外部知识API端点设置为容器可访问的后端地址。本机为 http://host.docker.internal:8003/api/v1/student/knowledge，并设置服务端生成的STU_KNOWLEDGE_TOKEN。Dify会调用/retrieval；两份外部知识库分别使用knowledge_id Germany、Singapore。此密钥只在服务器和Dify管理配置中保存，不能放到前端或交接包。外部接口只能读取公开生活资料。

本机服务端配置 STU_ASSISTANT_MODE=workspace 和原学生应用的 STU_DIFY_API_KEY，沿用 logs/integration-dify.local.json 中其他模块配置。前端 http://127.0.0.1:5193/website/student，后端环回8003，Dify工作室 http://127.0.0.1:18088/apps。密钥和数据库配置不提交Git。

presentation_json字段保存服务器生成的卡片和选择项，刷新后可恢复展示。最近8条消息与最多5条相关记忆用于上下文；学籍事实、用户自述和待办草稿分别管理。
