# 当前学生助手答复流程（v5，2026-11-17）

## 网页消息处理

1. 服务端确认本人身份及会话归属，加载当前资料、最近8条用户/助手消息、本会话草稿及最多5条本地记忆。
2. 保留原高风险处理路径。普通公开问题先按当前原话判断类别、对象、国家；省略追问只从最近用户原话承接可靠主题，遇到业务或无关新话题会停止沿用。
3. 本人学籍/院校申请/考务查询由后端按本人范围读取并生成事实卡；明确“我要请假”等入口可直接生成待补资料的草稿，不等模型。
4. 只有需要从较完整请假/反馈原话中提取字段时，调用一次Dify规划分支，整体预算5秒。字段仍须为当前原话，正式提交仍由本人确认、版本和后台事务状态机控制。
5. 命中审核FAQ的公开知识直接返回简短审核正文和一个主来源入口；普通问优先当前对象的一条主答，明确多问才组合必要不同方面，额外官方来源在同一来源入口展开。保留完整FAQ供“详细一点”使用，不通过模型复述全文，也不把完整静态答案假拆成打字效果。
6. 普通交流/支持仅调用一次Dify可见回复分支，按检查过的完整句流式显示。默认简短回应当前事项，用户需要详细时再展开；未经证实的个人阶段、联系方式及代办承诺仍被检查。
7. 模型超时/中断或不通过校验时，清除未完成文本，返回后端安全答复。最后保存聊天和必要的显式自述记忆，并保留原对话保存失败提示与本地回执。

## 等待预算与真实流式

公开知识和官方事实不需要模型调用即可答复。普通模型回复采用上游首个非空正文6秒、整个调用12秒的预算；这不是承诺网页必在6秒出现完整句，因为完整句仍需通过检查。业务字段规划预算5秒。

心跳和纯空白不是首内容，不能延长墙钟截止。调用被取消/超时会关闭本地HTTP读取，不留下本地生成任务；没有声称能保证取消Dify服务器或供应商端任务。其他模块调用chat_messages时不传新预算，保持原默认兼容。

## 画布与数据边界

仍发布到同一22节点学生应用。知识库保留德国、新加坡两个外部检索入口，数据源仍是审核导入的overseas_life_knowledge；72FAQ各有short_answer和完整answer。学生网页登录令牌不会传给只读模型。Dify不能提交、确认或批准业务。直接Dify预览的原兼容分支与网页实际路线不同，判断网页效果须从学生网站实测。

## 前端展示

公开知识使用紧凑来源/详情链接，来源标题、地区、核对日期及额外来源可展开。本人业务事实卡保持完整。新答复优先定位正文开头；用户手动滚动后停止自动跟随，可主动回到最新回复。立即清空输入、保留等待时输入、失败恢复、跨会话迟到回复保护、多轮未入库问答提示、附件版本和本地记忆管理沿用v4。
