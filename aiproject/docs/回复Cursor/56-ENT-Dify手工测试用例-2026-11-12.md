更新日期：2026-11-12。下面直接写明每一步怎么操作；按正文顺序从 M30 开始做，再继续 M01。编号沿用原46条用例，便于填写57号记录表。当前各条均待你自行执行。

## 第一步：打开测试页面

1. 在本机浏览器打开[已发布的 ENT 对话页面](http://127.0.0.1:8088/chat/QPbxdHVh0wrX1Exi)。该地址已核对可访问；应进入对话界面。
2. 如果页面显示“Start Chat”（开始对话），先点击它，进入可输入消息的界面。
3. 找到页面底部的消息输入框，以及输入框旁的发送箭头。
4. 找到左侧“Start New chat”（开始新对话）入口。侧栏收起时，先点击左上角菜单展开。英文名称来自当前页面资源；中文界面的措辞可能略有差异。
5. 在 Cursor 或文本编辑器中打开[57号测试记录表](<D:/Project course/group_wuweiwen_yujiao/aiproject/docs/回复Cursor/57-ENT-Dify手工测试记录表-2026-11-12.md>)。每测一条，将对应行的“待测”改为实际结果，并填写“已发布入口”或“预览入口”。
6. 先执行下面的 M30 健康检查。它通过后，再执行后面的用例。

本版对应 v3 修复图，发布ID为105f3a44-ad5a-444f-8e66-98ec696deb69。当前可信员工身份未接入，所以查询或确认提交后应说明实际HTTP503，而不是显示业务数据或宣称保存成功。示例编号1、20、1000001、1000004仅用于当前拒绝模式的路由测试；如果身份已经接通，先停用这批示例写入，按文末J组改用专用测试记录。

## 第二步：需要核对运行记录时这样做

1. 先完成每条用例的回复检查。如果已发布页面不能查看节点细节，在记录表写“回复符合，轨迹未核验”，不要把整条填为完全通过。
2. 需要检查节点时，打开[工作流控制台](http://127.0.0.1:8088/app/ac18cfb8-3f60-406f-99dd-d9cc635dc71f/workflow)。如跳到登录页，正常登录Dify后回到此链接。
3. 打开该工作流的预览/调试对话面板，在面板内新建或重置会话，然后照下方步骤重新发送。同组要从第一条开始，不能只重放一条“确认”。
4. 回复结束后，打开这一轮可见的运行详情，核对下方每条指定的节点及输出。预览结果单独记录，不能拿另一轮预览的轨迹冒充原来已发布消息的证据。若仍无法看到节点参数，保留“轨迹未核验”，保存时间和消息/运行ID供之后检查。
5. 查看业务节点时，名称与ID对应如下：GET调用业务API=http_get，POST调用业务API=http_post，PUT调用业务API=http_put，PATCH调用业务API=http_patch。代码节点“验证动作、参数、确认与编号”就是plan。

每轮都会先做健康检查。“业务HTTP不执行”允许health执行，指上面四个业务节点不执行。若某轮health失败，该轮标为环境阻塞。Dify遇到实际503并经错误分支回复后，可显示partial-succeeded（部分成功）；只有错误确为503且回复正确时才符合这批拒绝场景的预期。

发送后等本轮回复完成再操作；不要把多条内容一次发出、连续点击发送或在同组中途新建会话。所有结果按“通过/失败/阻塞/未核验”填写，不能把503算作保存成功。

### J10 使用两名真实测试员工核对权限

准备：管理员已准备A、B两名测试员工的可信访问方式及明确的数据范围。Dify网页账号不等于后端员工身份；若无法证明两个入口对应不同principal，本例阻塞。

1. 通过已配置的可信登录链路进入员工A的测试入口。记录A的身份与已获授权的数据范围，不使用自填X-Employee-Id。

2. A按J01流程创建一条专用测试客户，记下客户ID；确认B未被授权访问该客户。

3. 通过已配置的可信链路进入员工B的独立测试入口，创建新会话，把<A的客户ID>替换成第2步真实返回值后发送。

```text
查看客户<A的客户ID>详情
```

   检查：后端403，不返回A客户的详细资料；不能用一个不存在的ID返回404来冒充越权测试通过。

4. 管理员提供一个真实存在、且明确不在B授权学生范围内的测试学生ID。B新建会话后发送。

```text
查询学生<不在B范围内的测试学生ID>的成绩
```

   检查：后端403，不返回该学生的成绩内容。

5. 再由B使用明确在本人范围内的测试学生ID，新建会话发送。

```text
查询学生<在B范围内的测试学生ID>的成绩
```

   检查：后端正常查询成功，结果只来自其授权范围；用来排除所有请求一律失败造成的假通过。

6. 记录A/B可信身份的核验依据、数据ID、403和正常查询结果，填写J10；记录中不要复制令牌或Cookie。

## 每次测试后如何填写结果

1. 回复和本轮运行记录都符合预期，填“通过”。
2. 回复正确但节点/数据看不到，填“未核验”，写明看不到哪一项。
3. 后端健康失败、可信身份未接通或缺少专用测试数据，填“阻塞”及原因。
4. 行为不符，填“失败”，复制实际回复，并保留用例编号、会话前文、测试时间、运行/消息ID和截图。
5. 不要把模型失败、沙箱错误、网络超时统一当成预期503；不要把“部分成功”理解为数据保存成功。

M组完整核验后应有46条记录：19条不调用业务HTTP，27条各调用一次业务HTTP并得到实际503。J组只在身份链路和测试数据准备完成后单独统计。

转派、多进程并发和通知去重还涉及当前Dify未提供的操作入口或后台扫描，不能只用这些对话完成全部验收；这里不编造转派命令。
