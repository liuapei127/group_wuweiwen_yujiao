## 2. HTTP验收矩阵

以下为目标契约，具体防枚举策略、幂等策略及角色范围应与团队一致，并在记录中明确。403要求凭据有效且身份可信，不能仅把任意员工头视为可信身份。

| 用例 | 目标结果 | 数据核验 |
| --- | --- | --- |
| 正常创建→列表→详情→合法状态→再查 | 约定成功状态，数据一致 | 独立SELECT核验本次创建ID与标记 |
| 无Bearer、错误Bearer | 401，各业务路由均不得放行 | 无新增、无修改、无跟进写入 |
| 未配置服务token | 使用单独启动配置验证503，不影响正常实例 | 业务不执行，不输出密钥 |
| 缺少、非法员工标识 | 按团队契约401或422；不得静默跳过身份 | 无副作用 |
| 可信员工A操作B的客户 | 403，或已明确的防枚举404策略 | 状态、负责人、跟进均不变 |
| 同token篡改员工头为负责人 | 修复前真实记录；修复后不能借此改变操作者 | 不泄露客户、不产生越权写入 |
| 凭据身份与头、body员工或role冲突 | 拒绝，或忽略不可信字段并采用凭据身份 | 不能通过字段篡改提升权限 |
| 不存在或已停用员工 | 不得作为有效员工执行请求 | 无业务副作用 |
| 客户创建指定其他owner | 仅已定义且授权的分配操作允许 | 无权分配不能生效 |
| 列表、详情及跟进访问 | 按员工/角色范围过滤与授权 | 不泄露他人数据 |
| 有效身份访问不存在客户 | 404，或统一防枚举策略 | 不出现伪成功 |
| 非法枚举或字段 | 422 | 无非法数据 |
| 非法状态转换 | 409 | 保留原状态 |
| 重复更新同一状态 | 按明确幂等或冲突契约 | 不制造重复副作用 |
| 负责人新增跟进后查询 | 跟进内容与记录一致 | 独立查crm_follow_up及关联客户 |
| 非负责人新增跟进 | 拒绝 | 无新增跟进 |
| 数据库不可用或事务失败 | 按约定错误响应，异常脱敏 | 必要回滚，连接释放 |

真实身份链路未就绪时，可用仅存在于测试代码的依赖覆盖验证应用内授权逻辑，但必须标记为应用内测试；不得作为真实HTTP身份验收。权限漏洞尚存时，保存复现结果并明确失败，不把当前可伪造行为设为最终通过预期。
