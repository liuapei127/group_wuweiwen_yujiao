# 46 测试问题分析与修复说明

日期：2026-11-11。范围：ENT 本地代码、验证工具及开发依赖。

## 已确认并修复

| 问题 | 原因与触发条件 | 修复 |
| --- | --- | --- |
| UTF-8 模式测试失败 | 父 Python 使用 UTF-8，子 Python 仍按 Windows 默认编码输出中文异常；subprocess 读输出时出现 UnicodeDecodeError，继而 stderr 为 None | 测试及备用检查脚本对子 Python 显式使用 -X utf8，同时指定 encoding=utf-8，不吞掉异常 |
| TestClient 弃用警告 | 本机 Starlette 1.10.0 优先使用 httpx2，原环境只有 httpx 0.28.1 | 安装 httpx2 2.16.0；在 pyproject 的 dev 依赖声明 httpx2>=2.16,<3；保留旧脚本使用的 httpx |
| 停用或已删除学生仍能改成绩 | 成绩创建检查学生存在且启用，但更正接口遗漏检查 | service 中统一学生有效性检查；两种情况返回422，数据库成绩保持原值。新增两个回归实例，修复前均复现200，修复后通过 |
| 把第二轮有新增误报为去重失败 | 每类来源每批最多200条；超过200条时第二轮继续产生待办是正常推进 | 验证按来源类型+业务ID核对恰好一条待办；新增201张请假的分批回归，第二轮新增一条是合法推进 |
| 验证扫描可能触及无关员工的数据 | 扫描器默认全库，原验证直接使用默认范围 | 后台扫描内部增加可选 employee_ids；验证仅扫描专用测试员工，未新增对外扫描接口；默认后台全量行为保留 |
| 默认值检查可能漏报 | 原归一化会混淆0/空值，并忽略字符串大小写与空格 | 默认值单独比较，仅统一 CURRENT_TIMESTAMP 语法；增加回归 |
| 验证可能显示过期成功结果 | 异常路径没有写入本轮失败状态 | 异常时保存 failed 状态及错误信息；数据关联缺口单独报告 passed_with_data_gaps |
| 标准SQL无法解析或 -O 模式可能削弱检查 | 空解析结果未显式拒绝；优化模式会移除assert验证 | 无有效CREATE TABLE定义时拒绝审计；优化解释器在连接/补数前拒绝运行；新增无数据库访问的守卫测试 |

代码继续遵循 router/schemas/models/repository/service 分层。成绩修复位于 score/service.py，接口仅负责参数绑定和HTTP输出；扫描数据访问仍位于 todo/reminder_repository.py，事务由 reminders.py 包装。
