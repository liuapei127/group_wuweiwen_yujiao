## 3. P2剩余关键缺口

### 3.1 列表隔离存在测试假阳性，分页与total未断言

当前A使用ma（..._A），B使用mb（..._B）查询，各自关键词天然不命中另一员工客户。即使删除owner过滤，这组结果仍可能只返回本人创建的数据。list_no_cross_leak_in_page复用同一响应，没有设置page/page_size，total只写日志未与预期比较。因此它不能证明默认本人范围、分页及total隔离。

最小补测：使用两名员工都命中的公共MARKER；至少A两条、B两条，名字均包含同一标记。A/B分别查询同一关键词，page_size=1覆盖多个页面，逐页核对精确ID、owner、顺序和本人的total，确认没有他人ID。再用“对方专属关键词”查询，应items为空、total=0。保留已有显式他人owner=403用例。

若要证明不带关键词默认范围，在独立测试数据集/库中断言精确集合；已有混合测试库则至少核验全部返回记录owner正确，并用独立同条件SELECT计算总数。不要清理全库来制造可断言数据集。

将各请求HTTP状态、业务code及数据结构也作为通过条件；错误响应不可被get(...)/空列表默认值掩盖。

### 3.2 跟进没有完成同一记录的字段级一致比较

当前db_follow只查id、lead_id、employee_id、content；row_ok仅核对员工与content含标记；detail_ok仅核对任意跟进内容含标记。没有比较创建响应返回ID、详情记录ID、库ID是否相同，也没精确比较content，follow_type虽发送phone却未核验。

最小补测：从成功创建响应取得follow_id，按该ID查询数据库并从详情匹配同ID，比较id、lead_id、employee_id、精确content及本次发送的follow_type；若发送next_plan也一并比较。断言POST/GET的HTTP与业务code。日志保存同一条记录三方脱敏字段，不能只说“有标记”。

body员工冲突拒绝用例已具备计数核验，继续保留；补充拒绝前后匹配记录集合相同更清楚，不需要重复修复已生效403规则。

### 3.3 PATCH和运行证据一次补齐

本人PATCH同时发送contact_info与intended_country，但只检查contact_info。补两字段的响应、详情和数据库精确一致；保存他人拒绝前后脱敏快照与实际状态。已有五字段无变化断言有效，不将其重新标成未执行。

git_sha仅rev-parse HEAD，不能证明运行中的未提交脚本/代码就是该提交内容。附工作区差异和未跟踪源文件清单，或对本次相关源码生成归档哈希；不包含.env或凭据。对未来异常/超时也产出本次失败报告和外部实际退出码，维持既有原清单要求，不把run_id当版本或将计算的process_exit_code等同外部观察值。
