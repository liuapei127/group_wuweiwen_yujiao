# 50 并发验证、待办同步与成绩一致性

日期：2026-11-11。范围：ENT本地后端、本地MySQL迁移与隔离并发验证。

## 已实现

### 成绩去重与更正历史

新增请求字段与行为：

| 接口 | 新增字段/行为 |
| --- | --- |
| POST /api/v1/enterprise/scores | exam_key、submission_key均可选；返回id、version、replayed |
| PUT /api/v1/enterprise/scores/{score_id} | expected_version、correction_reason均可选；返回新版本号 |
| GET /api/v1/enterprise/scores/{score_id}/history | 按版本倒序查询历史；沿用scores:read及学生范围权限 |

exam_key标识该学生的一次考试；同一学生、同一标识最多一条成绩。未提供时，用规范化的课程名和学期生成稳定标识。因此同课程/学期的重考或其他考试必须传不同exam_key，不能靠重复POST制造多条记录。成绩量表仍不假定满分100。

submission_key标识一次提交，在同一学生范围唯一。相同标识和相同内容重试返回同一成绩；不同内容返回409。相同考试即使没有submission_key，相同内容也不会重复创建；同考试不同内容必须通过更正接口处理。如果该考试已由另一submission_key创建，传新key会冲突，不将未绑定的新key虚报为幂等成功。

提交指纹保留初次内容。成绩更正后重试原始提交只返回同一ID，不会将成绩改回初始值。

更正时锁定成绩行，检查版本号，并在同一事务中写成绩和历史。历史包含修改人、版本、原因、前值和后值；写历史失败则成绩回滚。相同内容不增加无意义版本。

为了兼容旧请求，expected_version不是必填；旧请求仍串行执行并保留历史。要拒绝过期页面覆盖，Dify/前端必须读取version并在PUT时传expected_version。实测四个请求同传版本1时，一个成功，三个返回409。

旧成绩迁移时写baseline，不虚构迁移前的更正记录。旧数据同一课程/学期存在多条时按legacy:<原ID>分别保留，不自动删除或猜测考试性质。

### 待办结案、取消与转派

- 请假approved/rejected后，对应待办变为done；源单取消时变为cancelled。
- 投诉resolved/closed后，对应待办变为done。
- 活跃源单转派后，待办负责人跟随变更，重置pending并增加assignment_version，新负责人可收到该修订的站内提醒。
- 活跃源单撤销分配或被删除时，旧待办取消；重新分配或源单重新打开时恢复pending并生成新的分配修订。
- 同一业务来源最多一条待办，不为每次转派重复建行。人工完成/取消但源单仍活跃时，普通扫描不会反复重开；负责人变更或真正重新打开源单时才恢复。
- 历史已发站内通知保留，不能将历史发送记录描述为已撤回；新负责人通知使用新的修订去重标识。

请假审批与投诉处理在同一业务事务中即时同步待办，失败时一起回滚。BASE/STU通过可信逻辑变更分配后，后台扫描负责同步；本轮没有新增允许普通员工任意转派的接口。

### MySQL并发保护

来源行先加锁，再读取/修改对应待办；批次使用SKIP LOCKED分配可处理记录。数据库唯一约束保护考试、提交、来源待办、成绩历史版本和通知去重键。通知去重键包含待办、接收人、分配修订号。

每类来源每轮最多处理200个需要变更的来源，通知每轮最多200条；后续批次继续推进。不会将“第二轮还有新增”误判为去重失败。

扫描遇唯一竞争、锁等待超时或死锁时，回滚后有限重试。真实多进程演练曾发现MySQL死锁使整个事务及其保存点失效，嵌套回滚会遮蔽原死锁；已调整MySQL插入路径，保留原始冲突供事务级重试。SQLite测试仍保留适用的保存点行为。

## 数据库迁移

新增student_score_history表，现有本地库共32张表。新增成绩身份/版本字段、待办修订/源状态字段及通知去重字段，并增加相关唯一索引。

迁移脚本：scripts/migrate_ent_reliability.py；迁移后结构校验基准：migrations/001_ent_reliability_expected.sql。主应用启动只注册模型，不自动迁移。

本轮已先在独立测试库演练，再对本机education_service执行。首次执行前备份位于logs/ent-migration-001-before.json（不提交git），并核对原有行及原有列内容保留。4条既有成绩新增4条基线历史。重复迁移actions为空，没有重复改表或增加基线。

MySQL DDL隐式提交，不能保证整个迁移失败后一次事务回滚；脚本可在修正冲突后重跑，不删除或自动合并既有数据。

原始标准SQL仍作为历史基准保留；检查工具检测到历史表后叠加001结构，当前32表所查结构差异为0，ENT关联缺口为0。
