# 客服记忆与客户画像研判改动说明

更新日期 2026-11-17

本次将官网客服收集的信息、游客提交的资料和顾问导入或补录的信息接入同一份客户画像。注册游客和负责该客户的顾问可以查看同一版本的资料，客户详情底部展示的 JSON 也是提交给 Dify 的研判输入。

## 客服会话与长期记忆

| 用户状态 | 使用方式 |
| --- | --- |
| 未登录访客 | 官网客服在当前标签页的 `sessionStorage` 中保存会话。刷新页面后可继续对话，点击“清空对话”可重新开始。请求携带最近的对话片段供 Dify 理解上下文。 |
| 已登录游客 | 后端根据登录身份读取共享画像，并通过独立的 Mem0 配置检索该账号的长期事实。客服将明确的本人陈述写入画像，后续对话可继续使用。 |

结构化画像以业务数据库为准。Mem0 检索结果需要与当前画像内容匹配，历史事实不会因为被检索到就覆盖当前资料。顾问或游客通过画像接口保存资料后，后台同步 Mem0。失败时进行短时重试，后续客服请求也会按当前画像重新检查同步状态。

## 画像字段和资料写入

- 客户画像统一维护基本信息、教育与能力、留学意向与需求、家庭与预算。年龄和学历各记录一次，语言能力可记录多种语言，技能保留动手能力和逻辑思维。新加坡与德国项目分别按《用户画像研判规则》读取所需字段。
- 游客尚未建档时，画像按已登录账号暂存，建档后按原账号关联并入客户画像。顾问通过客户详情导入资料时，先核对姓名和本人手机号，再预览并选择确认写入的字段。
- TXT、CSV、Excel 和 PDF 可通过已有资料入口处理。已登录游客提交的明确本人文字可以用于补充画像，有身份信息的文件通过核对后可提取字段。未能确认归属或提取字段的材料继续保留在原材料流程中。
- 画像属性保留来源、更新时间和确认状态。客服及自动提取发现与现值冲突的内容时，将候选值保留为待核对信息。已确认的修改使用画像版本校验，旧页面提交会收到冲突提示。

## 双端刷新和研判

顾问端在“客户管理 → 客户详情”查看画像，游客端在“我的资料”查看。保存后页面更新当前数据，另一端通过 SSE 接收版本变化并重新读取画像。页面重新获得焦点、网络重连或定时刷新时，也会补取最新数据。

客户详情底部的“用户画像与研判输入”以《用户信息数据示例》的单人 JSON 数组形式展示，支持复制。示例基础字段与一套通用的补充属性一起输出，技能细项也独立保存。缺失值按实际资料显示为空，标签权重来自已提供的资料。

本地初筛按所选项目核对年龄、学历及在读或毕业状态，同时展示其他规则属性和待补信息。德语 B1 属于德国企业匹配前需要核对的阶段条件。研判时保存完整输入快照、画像版本、规则版本和结果，画像更新后旧结果会显示重新研判提示。
