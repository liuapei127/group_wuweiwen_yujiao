## 五到七分钟演讲流程

### 0:00～0:45：介绍用途和处理方式

可以这样讲：

> 这是员工使用的企业助手。员工可以用自然语言查询客户、待办、日报和学生相关资料。助手通过 Dify 理解请求，再由后端核对身份、权限和操作字段，调用现有业务接口。涉及新增、修改和审批时，系统先展示待确认信息，员工确认后再提交。

处理顺序：员工提问 → Dify 理解意图和参数 → 后端核对权限与字段 → 查询，或等待员工确认 → 业务接口返回真实结果 → 页面展示。

### 0:45～2:00：查询真实业务资料

用普通员工账号，点击“新建对话”，依次输入：

```text
查询我的待办
```

```text
查询我的客户列表
```

可以这样讲：

> 这里返回的是当前账号有权查看的业务记录。待办可以看到编号、状态、优先级和到期时间；客户查询也限定在当前员工的权限范围内。查询结果会逐步显示，完整结果随后保存在会话中。

“你好”“你能帮我做什么”属于服务端快捷介绍，可以作为开场，但不能用它来证明 Dify 已连通。上面两条业务查询才经过真实 Dify 理解和接口调用。

### 2:00～4:00：展示确认、取消和真实写入

输入：

```text
新增待办，标题为下午演讲记录整理，说明为整理客户提出的问题并安排后续回访，优先级高
```

先展示确认卡片，核对标题、说明和中文优先级，然后点击“取消操作”。

可以这样讲：

> 助手先把我说的话整理成待确认信息。此时还没有创建待办，我可以核对，也可以取消。

再次输入同一条指令，核对卡片后点击“确认执行”。等系统返回成功和待办编号，再进入左侧“我的待办”，核对刚新增的记录，也可回到助手查询“查询我的待办”。

可以这样讲：

> 现在我已经确认提交，业务页面能够查到这条记录，说明自然语言操作已经落到现有业务流程中。系统对同一会话版本的重复确认有冲突保护。

如果已经预演过这个标题，现场换一个标题，例如“客户演示意见整理”，便于辨认本次新增记录。成功前不要连续重发新增指令。

### 4:00～5:15：展示角色权限和组织管理

切换经理账号，新建对话，输入：

```text
统计本周日报提交情况
```

或者：

```text
查看今天所管组织的日报
```

可以这样讲：

> 同一个助手会根据登录人员的岗位权限提供不同范围的数据。经理可以查看授权组织的日报和提交情况，普通员工只能查看自己有权限访问的资料。

如需演示生成报告，可输入“生成本周正式周报”，只展示确认卡片后点击取消。本次已验证到该确认环节；正式生成归档不是本轮现场检查的执行范围，不把草稿展示说成已经生成报告。

### 5:15～6:15：可选展示学生事务或语音

学生事务使用班主任账号，输入：

```text
查询我的待审批请假
```

```text
查询我的投诉工单
```

```text
查询学生1000202的成绩
```

本轮已验证这些查询，以及请假审批草稿和取消。现场保留真实学生事务状态；讲解审批流程时展示待确认卡片即可。

语音演示：点击“录音转写” → “开始录音” → 说“查询我的待办” → “结束录音并转写” → 核对转写草稿 → “插入消息” → 发送。语音转写不会直接代替员工提交操作。

### 6:15～7:00：展示会话记录和结束语

刷新页面，在左侧会话列表重新点开刚才的对话，展示问题、回答和操作记录仍然存在。

可以这样讲：

> 企业助手把查询和操作串在同一个工作入口里，员工不用记接口或菜单路径。操作保持确认流程，数据范围继续遵循系统原有权限，会话记录可以回看。

企业助手的会话历史与客服模块的 Mem0 用户画像不是同一项能力。本次不把企业会话记录介绍成跨会话的长期用户画像记忆。

## 现场异常时如何处理

- 查询等待期间继续解释权限或确认流程；若出现明确失败，先查看网络和模型服务状态，恢复后再重试查询。
- 写操作遇到断网或超时，先去业务页面核对是否已经保存，再决定下一步，避免重新发起同一新增业务。
- 本机三节点备用理解流程与主应用使用同一模型供应商，不能将它介绍为供应商故障时的独立保障。
- 模型服务临时不可用时，可以展示本机已保存的查询、确认卡片截图和业务页面，并明确说明正在展示预先验证的结果。
- 语音设备无法收音时，直接使用准备好的文字指令继续演讲。
